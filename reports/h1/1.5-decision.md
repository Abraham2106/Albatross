# 1.5 Decisión técnica integrada (H1)

Fecha: 2026-09-10. Responsable: Arquitectura (esta sesión). Estado: **En validación** — H1 no cierra: falta foto desde celular real.

## Evidencia reunida

| Pregunta | Resultado |
| --- | --- |
| ¿QVAC 0.18.2 lee una placa en esta Windows + RTX 2050? | Sí. VisionPsy Nano 460M Flash Q4_K_M + mmproj Q8_0, `image_no_upscale: 'on'`, `completion` con `attachments: [{ path }]`. |
| ¿La delegación nativa QVAC transporta texto e imagen y devuelve resultado sin fallback local? | Sí, entre dos procesos Node. Provider `startQVACProvider`, consumer `loadModel({ delegate: { fallbackToLocal: false } })`. |
| ¿Foto desde el celular real, sin internet? | No. La app es Expo SDK 57 (`apps/mobile-capture`) con adaptadores demo; el DHT no se midió sin internet. Desde el 2026-09-11 hay teléfono y SDK, así que el hueco es el development build, no el hardware. |

## Decisiones (hasta que 1.3 cierre)

1. **Modelo visual:** VisionPsy Nano Flash Q4_K_M (constantes 0.18.2), no Base, no OCR como camino primario. OCR_LATIN queda como alternativa local si 5.4 no alcanza calidad; no se atribuye a un VLM no ejecutado. Serie: un carácter erróneo en placa nítida (`A3T` → `ABT`); la revisión humana sigue siendo obligatoria.
2. **Dónde corre la inferencia:** siempre en la computadora. El celular no carga VisionPsy ni Qwen en este alcance.
3. **Transporte de inferencia:** usar la **delegación QVAC** (`startQVACProvider` + `loadModel({ delegate })`) para multimodal, STT y LLM. No presentar HTTP en LAN como delegación. `fallbackToLocal: false` en el cliente de campo.
4. **Transporte de aplicación:** la delegación QVAC **no reemplaza** el repositorio ni la aceptación. Capturas, manifiestos, pendientes, revisión e idempotencia siguen un canal de aplicación autenticado (paquetes 2 y 3) que invoca el orquestador local; ese orquestador llama a QVAC en la laptop.
5. **Plataforma móvil:** `apps/mobile-capture`, orientada a Android, sin iOS. Esta decisión se tomó el 2026-09-10 suponiendo Android nativo con Kotlin DSL y paquete `com.albatross.mobile`; **quedó superada el 2026-09-11**, cuando la app pasó a ser Expo SDK 57 con React Native 0.86.3 y paquete `com.philips.albatross.mobilecapture`. Consecuencia técnica: Hermes no ofrece UDP, así que el P2P en el celular exigirá un development build con `react-native-bare-kit`, no Expo Go. Este hilo no implementa 4.1–4.4; el peer de computadora expone los contratos que esa app consumirá.
6. **Memoria:** ~16 GiB RAM al 96 % con VisionPsy. Conservar cola secuencial (un modelo nativo a la vez) entre Whisper, Qwen y visión.
7. **Identidad P2P:** `QVAC_HYPERSWARM_SEED` debe ser hex de 32 bytes o ausente (identidad aleatoria). No usar frases.
8. **Worker Windows:** lock `%USERPROFILE%\.qvac\.worker.lock`; timeout RPC 30 s; arranque frío ~20 s. Un proceso QVAC por HOME. El consumer de laboratorio aisló HOME con `SNAP_USER_COMMON`.

## Limitaciones que bloquean declarar H1 terminado

- No hay celular real ni prueba sin internet.
- El firewall de claves del provider no se ejercitó.
- Elegibilidad del reto: no declarada (ISD completo no recuperado).

## Qué no construir todavía

No iniciar 4.x en este hilo (la app vive en `apps/mobile-capture`) ni 7.x (demo) hasta un teléfono y una corrida 1.3/7.2. Sí es razonable, con riesgo explícito, avanzar **2.x (contratos/persistencia)**, **3.x (peer de computadora)** y **5.1 (puerto visual)** porque no sustituyen a la app y la visión local ya está demostrada.
